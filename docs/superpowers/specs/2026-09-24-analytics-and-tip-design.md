# 结果页转化统计 + 赞赏码改版 — 设计说明

**日期：** 2026-09-24  
**状态：** 已实现（待填百度统计 ID 后事件才会上报）  
**范围：** 结果页轻量埋点、赞赏区半展开交互、替换微信小号赞赏码

---

## 1. 背景与目标

当前结果页已有「复制去发群 / 保存图片 / 赞赏」三个动作，但：

- 没有任何统计，无法知道测完后多少人愿意分享、留图、看赞赏
- 赞赏码默认完全收起，曝光弱
- 计划换成微信小号赞赏码，并优化展示方式

**目标（按优先级）：**

1. 能看见「有多少人对赞赏感兴趣」（以打开完整赞赏码为近似指标）
2. 同时能看见分享、保存的点击情况
3. 赞赏码更好被看见，但不做成「一进结果页就硬推销」
4. 真收了多少钱仍以微信账单为准，页面不做「已付款」统计

---

## 2. 已确认的产品决策

| 议题 | 决策 |
|------|------|
| 统计范围 | 分享、保存、赞赏都要；最关心赞赏兴趣 |
| 「赞赏了多少人」怎么理解 | 只统计「展开看清赞赏码」；不统计真实付款（钱看微信账单） |
| 赞赏区展示 | 默认半露出一小截码 +「展开看清」；点开再记事件 |
| 统计工具 | 百度统计（现成免费后台） |
| 赞赏码素材 | 已定稿：小号「云之海」，引导语「被戳中就投币，请作者续命可乐」 |
| 赞赏金额（微信侧设置） | 走小额好玩路线（如 `0.5 / 1 / 1.5 / 2 / 5 / 6.6`，以微信最终可设为准） |

## 4. 统计设计

### 4.1 事件列表

| 事件名 | 触发时机 | 用途 |
|--------|----------|------|
| `result_view` | 用户进入结果页且有有效结果 | 分母：测完人数 |
| `share_click` | 点击「复制去发群」 | 分享意愿 |
| `save_click` | 点击「保存图片」 | 留图意愿 |
| `tip_expand` | 点击「展开看清」（从半开 → 全开） | 赞赏兴趣（核心近似指标） |

**可选（本期可做可不做，建议顺手加上）：**

| 事件名 | 触发时机 | 用途 |
|--------|----------|------|
| `home_view` | 进入首页 | 漏斗上游 |
| `quiz_start` | 点击开始测试 | 漏斗上游 |

### 4.2 转化率怎么算（后台人工理解即可）

- 分享率 ≈ `share_click ÷ result_view`
- 保存率 ≈ `save_click ÷ result_view`
- 赞赏兴趣率 ≈ `tip_expand ÷ result_view`（本期最关心）

### 4.3 明确不做

- 不记录、不推断「是否已付款」
- 不自建统计服务器 / 管理后台
- 不做复杂用户画像、A/B 平台
- 半露出状态下的「看见赞赏」**不**记为 `tip_expand`（避免人人进结果页都算感兴趣）

### 4.4 接入方式（百度统计）

**你（产品侧）负责：**

1. 注册/登录 [百度统计](https://tongji.baidu.com/)
2. 添加本站域名，拿到统计代码或站点 ID
3. 发给开发，写入项目

**开发侧负责：**

1. 在入口页接入百度统计基础脚本
2. 封装薄工具（例如 `src/utils/track.js` 的 `track(eventName, payload?)`）
3. 在上述时机调用自定义事件上报
4. 失败时静默忽略（不影响答题/结果页主流程）

## 5. 赞赏区交互设计

### 5.1 两种状态

**状态 A — 半开（默认）**

- 显示人设赞赏文案（继续用现有 `getRewardTip(result)`）
- 露出一小截赞赏码（高度裁切，例如约 40%～50% 可见，具体实现时按观感微调）
- 主操作文案：**「展开看清」**（或等价短句）
- **不**触发 `tip_expand`

**状态 B — 全开**

- 完整显示赞赏码图片
- 可保留短提示（可弱化「扫码赞赏，感谢支持」，避免和码上引导语重复）
- 提供 **「收起」**
- 进入全开时触发一次 `tip_expand`（同一结果页会话内是否去重：建议同一页只记 1 次，避免反复点开刷数）

### 5.2 与海报的关系

- 赞赏整块继续 `data-html2canvas-ignore`
- 保存的人格卡图片**不含**赞赏码

### 5.3 素材替换

- 用已定稿图片替换 `public/assets/reward-qr.png`
- 引用改为 `?v=3`（或更高），避免微信/浏览器缓存旧码
- 码上已有引导语「被戳中就投币，请作者续命可乐」；页面内按钮文案仍用人设 tip，两者可并存（按钮偏人设，码上偏统一行动号召）

## 7. 验收标准

1. 百度统计后台能看到 `result_view / share_click / save_click / tip_expand` 事件
2. 结果页默认半露出赞赏码；点「展开看清」后完整显示，并产生 `tip_expand`
3. 新赞赏码扫码可打开微信赞赏（小号「云之海」）
4. 保存图片仍不含赞赏区
5. 统计脚本异常时，不影响复制分享、保存图片、答题流程

---

## 8. 风险与注意

| 风险 | 应对 |
|------|------|
| 半开裁切不当，扫不了码或看起来像坏图 | 半开区不可扫；文案明确「展开看清」；全开后才方便扫 |
| 用户误以为页面知道谁付了钱 | 文案与文档都说明：钱以微信账单为准 |
| 百度统计在微信 WebView 偶发漏报 | 接受近似数据；关键决策用趋势而非绝对值 |
| 旧码被缓存 | 图片 `?v=` 升版本 |
